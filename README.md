# KET family assessment mirror

Parent phone/contact registration, multiple children per family, private cloud
progress and administrator-only assessment results.

Ordinary families do not need an email address or verification email. They enter
a child display name and parent mobile number only. No participant password is required.
The device keeps a standard private session; another device uses a parent-held
private resume link, generated on the signed-in family page. Same-device resume
requires a valid family session, never a matching name alone. Links last 30 days;
reissuing invalidates the old link for future use, not existing device sessions.
The phone is self-reported contact information, not verified ownership or real-name
identity. Knowing a number alone cannot retrieve historical records. Resume links must
remain with the family and are never included in answer exports or public logs.
The existing owner has a separate administrator entrance at ?view=admin.
The child entrance never displays the administrator search table or contacts.
The default child entrance shows only child name, parent mobile number and Start.
Existing/new family classification is internal; recovery help appears only after
an actual error, and detailed family guidance stays in collapsed parent settings.
Adding a confusing duplicate name asks for a distinct nickname instead of merging
children. A lost session or expired link opens contextual recovery. After a 401,
new inputs can be backed up only within the previously loaded family/child scope;
network reads and saves still require authentication. Confirmed local backups
allow a safe sign-out followed by private-link resume without losing the latest draft.

The main paper now follows Test 2 in original Part order: Reading Parts 1-5
(30 questions), then the separate Writing entry retains Parts 6-7 with original
images. The seven reading groups / 44 questions remain in the source model;
older Test 1 and Test 4 responses keep their original refs and source identity.
An existing Test 2 Listening Part 2 source recording is retained in assets and
prior response metadata. The current ordered listening entry is preparation-only:
Parts 1, 3, 4 and 5 recordings and their dedicated renderers are not yet complete;
it neither starts at Part 2 nor permits a new listening submission. Real speaking
prompts/pictures are preserved. The speaking recorder is visible with an environment reminder,
and supports stop, replay, local first-submission lock and audio export.
Recording remains device-local; automatic transcription is not connected.
Writing accepts camera/album photos, normalizes them to bounded JPEGs without
original EXIF, and saves them privately in the existing child response. A
submitted writing image cannot be replaced. Photos remain pending human review;
no OCR or external AI service is enabled. Child text/JSON exports carry image
metadata; the image itself can be downloaded separately.
Complete groups submit directly. Incomplete groups show only missing question
numbers plus Back/Submit. Answer cards and exposure/help surveys are removed.
Omitted conditions remain unknown; they are not silently set to independent.

Per-child drafts, first submitted answers, source references and conditions are
saved privately through Supabase. A saved message requires a server revision
acknowledgement. Concurrent edits do not silently overwrite another device.
Ordinary parents can access only their own children. The explicitly approved
operator can search parent phone and child, inspect actual responses and export
CSV/JSON. Child-facing copy/TXT/JSON exports omit parent contact metadata; owner-only
management exports retain authorized contact information. Resume links/session tokens
are excluded from every export. This site stores assessment records; other-module
practice is excluded.

Objective results mean agreement with reviewed local source keys, not official
Cambridge scores. Writing, speaking and unlisted open-answer variants remain
pending review, never fabricated zero scores. Source keys remain server-side.
Whole-group submission opens a server-confirmed receipt, never family-facing scores.
The receipt shows submission success and Contact Teacher with an empty reserved QR
area. No booking destination is configured. Family APIs, including the old /result
URL, return only allowlisted save/submission receipt fields. Administrator-only
queries retain scoring, raw responses and contact details. Family text/JSON exports
are raw-response backups without grades or analysis. Saving errors do not display
success. QQ SMTP delivery runs only on the private backend, once per newly
submitted group. SMTP/provider acceptance does not prove inbox receipt. Unknown
outcomes are not automatically retried; every event can be claimed automatically
at most once, including configuration failures. Pending events have no independent worker.
The authorized operator has a one-time no-child-data technical test and a separate
read-only delivery-status table with state-specific manual guidance. Each assessment
event has a private frozen-receipt download for manual handling; downloading neither
sends mail nor changes delivery state. Recovery requires the existing operator role.
Reading email summaries separate matches, mismatches and unanswered items and retain
the non-official-score limitation. No email-sent claim appears in the child interface.
RW2 keeps its authentic repeated three-person options with independent per-item selection.
Initial registration fields render before the cloud probe completes; startup and
HTTP waits are bounded with retry. Existing family records are not rebound to a
new phone by opening the separate registration entrance in family settings.

Public source display follows the owner's existing publication authorization;
this is not publisher licence certification or an official Cambridge service.
No server key, reference key registry, private child data or technical fixture
is published in this repository.
